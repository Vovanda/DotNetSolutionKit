# ADR-006: JSON Metadata Key Convention

**Статус:** принято, 06.10.2026

**Автор:** Владимир Савкин, создатель DotNetSolutionKit

## Контекст

Шаблон и `dotskit` пишут JSON-файлы: `appsettings*.json`, манифест `.dotskit/manifest.json`, `features.json`,
`version.json`. В них есть поля, которые человек заполняет или читает, а многие пустые специально: строка
подключения, пароль, ключ. Прямо у поля нужно видеть, что туда вписать и запустится ли сервис без значения.
В JSON (RFC 8259) комментариев нет.

## Решение

Соглашение - мини-DSL поверх JSON: синтаксис - служебный ключ, словарь - его виды.

```text
JSON
 ├── data
 │    └── DefaultValue
 │
 └── metadata
      └── _comment_DefaultValue
```

### Синтаксис

Ключ, который начинается с `_`, - метаданные, а не данные.

```text
metadata-key  := "_" kind [ "_" name ]
kind          := identifier without "_"
name          := identifier

"_comment_DefaultValue"        kind: comment, name: DefaultValue - the field
"_comment_Defaults"            kind: comment, name: Defaults - a topic of the object
"_comment"                     kind: comment - the object or the file
```

### К чему относится

- `_<вид>_<Имя>` относится к полю `<Имя>` того же объекта и стоит сразу после него.
- Если поля с таким именем нет - к теме объекта с этим именем, как `_comment_Defaults`.
- `_<вид>` без суффикса относится к объекту или файлу целиком.

### Словарь

- Первый вид - `comment`: что вписать в поле и что будет без значения.
- Комментарий, начинающийся с `REQUIRED`, отмечает значение, без которого сервис не стартует.
- Новые виды подчиняются тем же синтаксису и правилам отнесения.

```json
"DefaultValue": "",
"_comment_DefaultValue": "REQUIRED: the threshold a call falls back to"
```

### Чтение и запись

- Приложение читает только объявленные поля и игнорирует неизвестные: конфигурацию - типизированными опциями
  (`IOptions<T>`), манифест и другие файлы - разборщиком, который пропускает незнакомые ключи. Метаданные -
  частный случай незнакомых ключей, отдельной обработки у них нет.
- Соглашение действует для каждого JSON, который генерирует шаблон или пишет `dotskit`, и для ключей, которые
  добавляет команда: это правило есть в инструкциях агента в решении.
- Форматы со своими комментариями (YAML, XML, `.props`) его не используют.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| отдельная дока | расходится с файлом, при правке её не открывают |
| комментарии в файле (JSONC) | `jq`, строгие разборщики и часть редакторов файл отвергают, а инструмент, который переписывает файл, их теряет |
| ключ `"//"` | одно пояснение на объект: повтор ключа - ошибка JSON, редактор её подчёркивает |
| JSON Schema с описаниями | видно только при подключённой в редакторе схеме, текст в другом файле |

## Плюсы

- Пояснение видно там, где смотрят: в редакторе под полем, в diff ревью рядом с изменённым значением.
- Поле и пояснение меняются в одном месте, поиск по ключу находит и пояснение.
- Файл остаётся валидным JSON, редактор ничего не подчёркивает.
- Метаданные - это данные: копирование и перезапись файла их не теряют.
- Соглашение проверяет машина: `scripts/check-json-metadata.py` в каждой комбинации `template.yml` не
  пропускает пустое поле без `_comment_`.
- Словарь растёт новыми видами без новых правил.

## Цена

- Настоящее поле с `_` в начале называть не стоит: читателю придётся разбираться, метаданные это или данные.
  Поля конфигурации редко начинаются с подчёркивания, риск ничтожный.
- Файл длиннее: на каждое поясняемое поле - строка.
- Соглашение нужно соблюдать во всех JSON, которые мы пишем.

## Риски и что с ними делаем

| Риск | Что делаем |
|---|---|
| метаданные доходят до приложения | неизвестные ключи при чтении игнорируются и в объект опций не попадают; сырой `IConfiguration` в коде не читается |
| в комментарий попадает секрет | комментарий говорит, *что* вписать в поле, без значений; CI шаблона проверяет каждое сгенерированное решение на секреты, а решение с `--GitHubCiCd` проверяет свои пуши |
| код, сохраняющий JSON, сортирует ключи | `_comment_X` уедет от `X`; пишущий код сохраняет порядок прочитанных ключей, а манифест `dotskit` получает фиксированный порядок (#102) |
